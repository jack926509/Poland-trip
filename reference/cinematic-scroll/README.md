# 電影感捲動參考頁

## 這是什麼、為什麼會有這個資料夾

這是一個**參考頁**，不是要上線的產品頁。

你之前拿到一份外部參考規格（波士尼亞 Mostar 城的電影感捲動網頁，附完整座標、
顏色、動畫數字），想知道「如果把這套捲動編排手法套在我的波蘭行程站上，會長怎樣」。

這個資料夾就是把那套手法原封不動抄一份，再把**文字內容**換成你的波蘭行程，
讓你可以親眼捲一遍、感受這套效果，再決定要不要、以及要挑哪幾招搬到正式站。
它不會影響、也不會出現在你正式上線的網站裡（見下方「與正式站的隔離」）。

## 怎麼打開來看

在專案根目錄（`Poland-trip` 這一層）開一個終端機，執行：

```
python3 -m http.server 8765
```

接著用瀏覽器開：

```
http://localhost:8765/reference/cinematic-scroll/
```

打開後**慢慢往下捲**，整段編排總共約 3700px 高（大約捲 4 螢幕的量）。
看完按 `Ctrl+C` 結束終端機裡的伺服器即可，不會留下任何東西。

## 哪些是波蘭、哪些還是 Mostar（這裡最容易誤會，請先看這段）

一句話講完：**你看到的是「編排手法」，不是「波蘭真的長這樣」。**

**文字全部是波蘭行程**：大標題、五張景點卡（皇家城堡、Wawel 城堡、Kazimierz
猶太區、百年廳、教堂島）、兩塊故事面板（華沙老城、克拉科夫中央市集）的內容，
都是照你 `redesign/data.js` 裡實際的 8 天 4 城行程寫的，地名沒有一個是編的。

**七張場景圖裡有六張仍然是波士尼亞 Mostar 的橋和市集**，這是刻意的，不是忘了換：
這六張圖是「透明去背的分層插畫」——天空一層、遠山一層、市集一層、橋分左右
兩半各一層——整套捲動時的立體視差效果，靠的是這些圖層的透明邊緣互相疊在一起。
你行程站裡的照片是矩形的 webp 檔，硬換進去邊緣會露出方形黑邊，
整套視差跟分層效果會直接壞掉，所以這一批圖沒有換。

**有換的例外（第七張場景圖＋景點卡縮圖）**：
- 七張場景圖裡的最後一張，一張全螢幕淡入的特寫圖，已經換成你的
  `krakow-hero.webp`（克拉科夫市集廣場）。
- 五張景點卡上的小地標縮圖，已經換成各卡所屬城市的縮圖（華沙／克拉科夫／
  樂斯拉夫／波茲南）。

**配色也還是 Mostar 原本的奶油色配藍色遮罩**，這階段刻意不換成你正式站的配色
（紅底奶油色），因為藍色遮罩是跟這批橋、市集的圖一起調過的，硬套你的配色
兩者會打架、變得很難看。要不要做波蘭配色版，等你看過這版效果後再決定。

## 已知限制（先講清楚，不是等你發現才說）

1. **頁面總重約 32.3 MB**（6 張遠端場景 PNG 合計約 32.2 MB、本地圖約 79 KB，
   2026-08-03 實測）。光是天空那張 PNG 就 8.3 MB、橋的圖 2.8 MB，
   這是外部規格圖檔本身的重量，不是做壞了。網路慢的時候第一次打開會等比較久。
2. **場景圖是別人網站上的檔案，隨時可能失效**。這六張 Mostar 圖是連到第三方
   網站（不是你的伺服器），2026-08-01 實測全部正常，但對方哪天改版或關站，
   圖就會消失。這頁只適合當「短期看效果用」的參考素材，不適合長期留著當資產。
3. **斷網就整頁空白，無法離線瀏覽**。這跟你正式站「斷網也能用」的 PWA 能力
   剛好相反——這正是為什麼不建議把整套手法原封不動搬上正式站的主要原因之一。
4. **標題字型讀不到，會退回系統預設字型**。規格指定的標題字型放在第三方的
   圖檔加速站上，那個網址不允許跨網站讀取（技術上叫 CORS 限制），瀏覽器會擋下
   這個字型請求，標題因此改用系統內建字體顯示，不影響其他內容。驗證腳本已經
   知道這件事，把它列為「已知會發生、不算失敗」的項目。
5. **「減少動態效果」模式下，連按輪播右鍵約 10 次會捲出空白**。如果你的電腦
   系統設定開了「減少動態效果」（accessibility 裡常見的選項），景點卡輪播在
   這個模式下連續按右鍵鍵到第 10 次左右，卡片會捲出可見範圍變成一片空白。
   這是照抄來源規格的行為（該模式下卡片切換的動畫過場被關掉，原本靠「動畫播完」
   觸發的循環重置邏輯因此不會被觸發），照抄規則優先所以沒有修，但你應該知道
   有這個狀況。一般瀏覽（沒開減少動態效果）不會遇到。

## 與正式站的隔離（不會影響你正式上線的網站）

這個資料夾**不會**被打包進你正式部署的網站：

- `prepare-site.sh` 是逐一列出要複製哪些檔案（白名單方式），`reference/`
  這個資料夾根本不在清單上，所以不管怎麼跑都不會被複製出去。
- 專案的自動測試裡有一條專門守這件事：只要 `reference/` 不小心跑進了部署輸出，
  測試就會直接紅燈失敗，逼你注意到。

換句話說：這頁只存在於你本機、只有你自己打開網址才看得到，正式網站的訪客
完全看不到、也不會被影響。

## 怎麼驗證這頁沒問題

有兩個驗證指令，用途不同：

**1. `./verify.sh`**（在專案根目錄執行，不連網，CI〔部署前自動跑的檢查流程〕會自動跑這個）

```
./verify.sh
```

這是全站的自動驗收，會順便確認 `reference/` 沒有偷偷跑進部署清單、
程式碼語法都正確。這個指令不下載任何遠端圖，跑起來很快、很穩定。

**2. `verify-visual.mjs`**（需要連網，手動執行，會下載約 32 MB）

這支腳本會實際打開瀏覽器把頁面跑一遍，捲到 8 個不同高度各截一張圖、
檢查動畫公式算出來的數值對不對、檢查全部圖片是否都正常載入、
測試輪播連續按 8 次會不會出錯。第一次要先在專案「外面」裝一個獨立的瀏覽器
測試環境（裝在 `~/.cache`，不會弄髒這個專案）：

```
PW_DIR="$HOME/.cache/polska-verify"
mkdir -p "$PW_DIR"
(cd "$PW_DIR" && npm install playwright@1.62.1)
PLAYWRIGHT_BROWSERS_PATH="$PW_DIR/browsers" "$PW_DIR/node_modules/.bin/playwright" install chromium
```

裝好之後，之後每次要驗證就跑：

```
python3 -m http.server 8765 &
PLAYWRIGHT_BROWSERS_PATH="$HOME/.cache/polska-verify/browsers" \
  node reference/cinematic-scroll/verify-visual.mjs
kill %1  # 關掉上面用 & 在背景啟動的本機伺服器
```

跑完會在終端機印出一串 PASS／FAIL，並在 `reference/cinematic-scroll/screenshots/`
資料夾（這個資料夾不會被提交進 Git）留下 8 張捲動截圖可以自己再看一次。

**為什麼這支腳本不放進 `./verify.sh` 一起自動跑？**
因為 `./verify.sh` 是每次要部署正式站前都會跑一次的把關指令，
而這支視覺驗證腳本要下載約 32 MB 的遠端圖片，把這種會連網、會失敗（例如網路
不穩、對方網站暫時掛掉）的步驟塞進部署流程，會讓部署本身變得不穩定、
偶爾莫名其妙卡住或失敗。所以刻意把它獨立出來，只在你想確認畫面效果時手動跑。
