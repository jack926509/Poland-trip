## 交叉審查與回歸修正

獨立 AI 審查在第一輪發現：單檔版點選搜尋結果後，網址與頁面雖正確，但單次 `requestAnimationFrame()` 可能被瀏覽器原生 hash 導航時序覆蓋，沒有捲到指定小節。

修正方式：先加入會失敗的回歸契約測試，再將單檔章節切換改為雙層 `requestAnimationFrame()`，等待 hash 預設導航與版面更新完成後才執行 `scrollIntoView()`。

修正後以 Chrome 390×844 真實點擊「華沙 → 克拉科夫」結果：

- hash：`#page-practical-booking--rail-itinerary`
- 顯示頁：`page-practical-booking`
- 目標頂端：96 px，已進入 844 px 高的可視範圍。
- 水平溢出：0 px。
- Console error：0。

第二輪程式碼審查修正項目：

- 行程索引改採公開欄位白名單，頁級索引排除 `private` 與 `data-search-private` 區塊。
- 餐廳名稱以標點與空白正規化後去重，解決 `E. Wedel`／`E.Wedel` 重複 ID。
- 多詞標題命中優先於一般關鍵詞；城市名稱支援不輸入波蘭文變音符號。
- 移除不適用的 `aria-expanded`，快捷分類補上群組語意。
- Escape 改由整個搜尋元件接收，並補齊鍵盤與隱私回歸測試。
- 搜尋、首頁必要資訊與前後章節導覽符合 16 px／44 px 行動裝置基準。

修正後索引為 200 筆、200 個唯一 ID，內嵌 JSON 為 228,508 bytes；敏感欄位測試哨兵與所有私人資料條目標題均未出現在正式輸出。
