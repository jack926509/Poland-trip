# Poland-trip 專案體檢與優化開發清單

日期：2026-09-06（Asia/Taipei）

## 目標與範圍

本輪直接針對目前的資料驅動靜態網站進行體檢、修正與驗收。正式來源限於 `src/data/*.js`、`src/templates/*.mjs`、`src/styles/*.css`、`src/scripts/*.js`、`build.mjs`、`sw.js`、測試與驗收腳本；不得直接修改 `dist/` 或 `poland-travel-guide-2026.html`。

## 分工原則

- Sol-A（畫面層／前端互動）：只修改 `src/styles/main.css` 與 `src/scripts/nav.js`。
- Sol-B（旅遊內容／資料品質）：只修改 `src/data/*.js`。
- Sol-C（前後端工程／品質防線）：只修改 `sw.js`、`build.mjs`、`tests/*.test.mjs`、`verify.sh`。
- 主流程（整合／驗收）：整合三方結果、產出優化報告、依序執行完整驗收。
- 所有動態價格、班次、開放時間與預約狀態，沒有可追溯依據時必須保留「待確認」或「出發前重查」，不得改寫為已確認事實。

## Task 1：畫面層體檢與修正

**說明：** 檢查桌機、手機、淺色、深色、鍵盤操作與低動態偏好，修正影響閱讀、操作及視覺一致性的問題。

**執行清單：**

- [ ] 以既有紙上旅行誌視覺語言為基準，不另做無關改版。
- [ ] 檢查色彩 token，避免深色模式仍使用固定淺色背景或低對比文字。
- [ ] 內文、標籤、輔助文字維持可讀字級與行距；避免過度縮小資訊。
- [ ] 導覽、搜尋、篩選、展開控制與連結的可點擊高度原則上至少 44px。
- [ ] 320px、390px、768px、1280px 寬度不得出現非預期水平捲動。
- [ ] 表格只在自己的容器內水平捲動，頁面垂直捲動不被地圖或浮層鎖住。
- [ ] 鍵盤焦點清楚可見，導覽開關、搜尋面板與 `<details>` 可正常操作。
- [ ] 搜尋或導覽開啟時不造成背景誤操作；關閉後焦點回到合理位置。
- [ ] 尊重 `prefers-reduced-motion`，避免非必要動畫影響使用。
- [ ] 圖片、地圖或外部字型失敗時，核心文字與導覽仍可使用。

**驗收條件：**

- [ ] 桌機與手機首頁、每日行程、城市頁、實用頁均可閱讀及操作。
- [ ] 淺色與深色模式主要文字、連結、標籤、卡片具有足夠對比。
- [ ] 手機沒有頁面級水平溢出；導覽與搜尋不遮住主要內容。
- [ ] 鍵盤可完成開啟、切換、關閉，且焦點不遺失。

**相依性：** 無。

## Task 2：旅遊內容體檢與修正

**說明：** 以 2026-10-24 至 2026-10-31 的 8 天四城行程為主軸，檢查內容是否一致、可追溯、沒有把不確定資訊寫成已確認。

**執行清單：**

- [ ] 日期、Day 編號、城市順序、移動日與住宿城市一致。
- [ ] 華沙、克拉科夫、樂斯拉夫、波茲南的城市代碼與頁面對應一致。
- [ ] 景點、餐廳、交通、票券、購物、行前資訊沒有明顯重複或互相矛盾。
- [ ] 動態班次、價格、營業時間、預約期限標記為已查證／出發前重查／待確認。
- [ ] 已確認資訊保留來源或可追溯欄位；沒有來源時不新增猜測。
- [ ] 地圖座標與城市歸屬一致；既有待驗證圖釘保持待驗證，不自行猜座標。
- [ ] 行程節奏包含移動、寄放行李、報到、緩衝與休息，不排入明顯衝突時段。
- [ ] 訂票與待辦資訊能分辨「需要行動」、「已完成」、「等待開賣」與「出發前確認」。
- [ ] 公開資料不得含護照、保單、付款、訂位代碼或其他私人資訊。
- [ ] 自由行資料庫的分類、城市、狀態與公開性欄位能支援現有搜尋／篩選。

**驗收條件：**

- [ ] 8 天日期與四城路線在首頁、每日頁、城市頁及資料庫互相一致。
- [ ] 不確定資訊保留狀態標示，沒有新增無來源的肯定敘述。
- [ ] 地圖資料稽核為 0 筆無效，既有待驗證項目不被錯誤升級。
- [ ] 私密欄位檢查通過。

**相依性：** 無。

## Task 3：前端工程體檢與修正

**說明：** 檢查模板、搜尋、篩選、單檔打包、資產載入、無障礙語意與錯誤降級。

**執行清單：**

- [ ] 所有正式頁面由原始資料與模板建置，不在生成檔做永久修補。
- [ ] 多頁版與單檔版的連結、fragment、ID、`for`、ARIA 參照改寫一致。
- [ ] 全站搜尋索引不收錄私人資料，搜尋結果連結可到正確頁面／章節。
- [ ] 資料庫篩選的關鍵字、城市、分類、狀態、公開性與結果數同步。
- [ ] 使用者輸入與資料序列化經過安全處理，不形成可執行 HTML／script 注入。
- [ ] 外部地圖、字型或網路失敗時，頁面保留清楚的文字替代與可操作性。
- [ ] 圖片具有尺寸或合理版面保留，降低載入時跳動。
- [ ] JavaScript 錯誤不應讓全站導覽、文字內容或基本連結失效。

**驗收條件：**

- [ ] 23 頁與單檔版可成功建置。
- [ ] 搜尋、篩選、頁內連結及 ARIA 關聯的自動測試通過。
- [ ] 手機與桌機實際操作搜尋、導覽、城市／每日頁切換正常。
- [ ] 瀏覽器 console 無阻斷功能的錯誤。

**相依性：** Task 1、Task 2 的來源變更完成後統一建置。

## Task 4：後端／資料流程工程體檢與修正

**說明：** 本專案沒有常駐 API 後端，因此將「後端」界定為 Node 建置器、資料同步工具、Service Worker、部署組裝與驗收流程。

**執行清單：**

- [ ] `build.mjs` 清理與重建輸出時結果可重現，不殘留舊頁面或漏檔。
- [ ] 建置失敗要有明確錯誤，不產生看似成功但內容不完整的輸出。
- [ ] Service Worker 版本與資產清單一致；預快取失敗時不可用殘缺版本取代舊快取。
- [ ] 同源核心資產可離線使用；第三方資產失敗不阻斷核心頁面。
- [ ] 舊快取只在新版本完整可用後清理，並保留安全的網路／快取降級策略。
- [ ] Dashboard 同步工具只更新公開安全欄位，資料格式不正確時拒絕寫入。
- [ ] `prepare-site.sh` 組裝內容包含正式頁面、必要資產、圖示、robots、sitemap 與 Service Worker。
- [ ] 驗收腳本按順序執行建置、測試與地圖稽核，避免同時重建 `dist/` 造成競態。

**驗收條件：**

- [ ] `npm run build` 成功。
- [ ] `npm test` 全數通過。
- [ ] `npm run audit:map-pins` 回報 0 筆無效圖釘。
- [ ] `env -u NODE_OPTIONS ./verify.sh` 完整通過。
- [ ] 離線或斷開第三方資源後，核心內容、導覽與既有快取仍可用。

**相依性：** Task 1、Task 2 完成後執行完整回歸。

## Task 5：優化報告

**報告必備內容：**

- [ ] 體檢日期、專案範圍與實際檢查入口。
- [ ] 每項問題的嚴重度、證據、影響、修正方式與修改檔案。
- [ ] 「已修正」、「確認無問題」、「保留待辦」三種狀態分開列示。
- [ ] 旅遊動態資訊另列出發前重查清單，不冒充本次已永久確認。
- [ ] 自動驗收與瀏覽器驗收結果分開呈現。
- [ ] 未執行的部署、推送或外部資料更新明確註記。

## 最終驗收順序

1. 執行 `npm run build`，確認 23 頁與根目錄單檔版產生成功。
2. 執行 `npm test`，確認所有資料契約、搜尋、篩選、打包與無障礙測試通過。
3. 執行 `npm run audit:map-pins`，確認 0 筆無效圖釘並保留待驗證數量。
4. 執行 `env -u NODE_OPTIONS ./verify.sh`，完成專案正式驗收。
5. 從專案根目錄啟動本機伺服器，驗收多頁版與單檔版。
6. 桌機 1280px、手機 390px 至少檢查首頁、Day 1、城市頁、資料庫及單檔版。
7. 驗收淺色／深色、鍵盤操作、搜尋／篩選、水平溢出、console 與離線降級。
8. 產出最終優化報告，附實際數字、失敗項目與尚待人工確認事項。

## 風險與處理

| 風險 | 影響 | 處理方式 |
| --- | --- | --- |
| 三路修改到同一檔案 | 高 | 採完全不重疊的寫入範圍，整合後才統一建置 |
| 動態旅遊資訊已變動 | 高 | 僅依可追溯證據修正，否則保留出發前重查 |
| 直接修改生成檔 | 高 | 只改來源，使用 `build.mjs` 重建 |
| Service Worker 殘缺快取上線 | 高 | 驗證 install／activate 生命週期與失敗回退 |
| 自動測試綠燈但實際版面有問題 | 中 | 加做 1280px／390px 實際瀏覽器驗收 |
| 外部地圖或字型不可用 | 中 | 核心資訊必須有同源或純文字降級 |
