# POLSKA 桌機分章雜誌設計規格

日期：2026-07-18（Asia/Taipei）

狀態：使用者已確認視覺方向；本文件只定義桌機網頁第一階段，不授權開始實作、合併或部署。

## 1. 結論

第一階段只完成桌機版「POLSKA — Travel Atlas」分章雜誌。桌機保留原版的紙本田野雜誌感，但不恢復一次向下閱讀全部章節的長頁；使用者每次只會看到目前選取的主章節或日次。

現有手機 PWA 在本階段保持原狀，不調整手機版面、`mobile.html`、manifest、PWA shortcuts、Service Worker 導覽 fallback 或安裝流程。手機版優化另立後續規格與實作計劃。

## 2. 成功標準

完成後應符合以下可檢查結果：

1. 電腦開啟根網址時，看到桌機雜誌介面，而不是放大的手機四分頁畫面。
2. 桌機頂部可切換「總覽、每日行程、交通與住宿、門票與預約、美食與城市、實用資訊、關於波蘭」。
3. 每次只顯示一個主章節；選擇每日行程後，每次只顯示 Day 1–8 的其中一天。
4. 重新整理、直接開啟章節網址與瀏覽器上一頁，均能回到正確章節或日次。
5. 日期、每日行程、火車班次、票價與訂票資料均取自 `redesign/data.js`，不得另建第二份核心行程資料。
6. 桌機版加入明確但節制的波蘭視覺元素，內容仍清楚易讀。
7. 現有手機 PWA 在本階段完成後仍維持目前行為，不因桌機改版而退化。
8. 自動驗收與 1440、1024、768 px 實際瀏覽器驗收全部通過後，才可宣稱桌機實作完成。

根網址的裝置契約如下：寬度大於等於 768 px 時顯示桌機分章雜誌；寬度小於 768 px 時仍顯示現有 `B_Companion` 四分頁介面。`?view=desktop` 與 `?view=mobile` 可人工覆寫寬度判斷，以便平板使用與驗收。這項分流只保護現有手機行為，不改造手機 UI 或 PWA 安裝流程。

## 3. 範圍

### 本階段包含

- 桌機雜誌殼層與固定章節導覽。
- 七個主章節及其單一主內容區。
- Day 1–8 日次切換、上一天、下一天與鍵盤方向鍵操作。
- Hash 路由、深層連結、瀏覽器返回鍵與未知 hash 降級。
- 桌機專屬城市、文化、歷史及實用資訊內容。
- 桌機資料載入失敗狀態與鍵盤焦點管理。
- 桌機資產的部署 allowlist、自動測試與實際瀏覽器驗收。

### 本階段不包含

- 手機版面或 `B_Companion` 功能優化。
- 將 `mobile.html` 改成新的正式 PWA 應用殼。
- manifest、PWA shortcuts、安裝流程或手機離線 fallback 調整。
- 登入、帳號、後端、資料庫、雲端同步或即時 API。
- 修改已確認的 2026/10/24–10/31 行程內容。
- 刪除 `archive/classic-index.html`、`styles.css` 或 `main.js`。
- 合併至 `main`、推送 GitHub 或部署正式網站。

## 4. 資訊架構

### 4.1 旅行總覽 `#overview`

顯示旅行日期、8 天 7 晚、四城路線、航班摘要、旅遊風格、高風險日與仍需確認的訂票事項。四個城市提供快速入口，但不在總覽一次展開全部城市文章。

### 4.2 每日行程 `#itinerary/day-1` 至 `#itinerary/day-8`

顯示單日標題、硬限制、逐時步驟、交通、費用、餐食、備案與實務節點。跨城日額外顯示火車出發、抵達、車種、價格與緩衝。日次切換支援按鈕、上一天、下一天及鍵盤左右方向鍵。

### 4.3 交通與住宿 `#logistics`

顯示航班、機場進城、跨城交通、車站、寄物、當地交通與住宿區域。內容以城市或日期切換，不同城市資訊不會同時全部展開。

### 4.4 門票與預約 `#bookings`

顯示必訂項目、建議期限、官方網址、適用日期及「尚未確認、已規劃」等資訊狀態。不新增會讓人誤認為跨裝置同步的虛假購票狀態。

### 4.5 美食與城市 `#cities`

先選城市，再顯示該城市的美食、景點、文化、購物及雨天備案。城市文章不複製核心日期、交通班次或票價。

### 4.6 實用資訊 `#practical`

包含天氣與穿著、安全與緊急聯絡、換錢、SIM 及常用波蘭語。內容使用可操作的折疊區塊，預設只展開使用者選取的主題。

### 4.7 關於波蘭 `#about`

包含歷史、節慶、文化與鄰國延伸閱讀。長文只在使用者主動選取此章時顯示，不加入其他主章節的頁尾。

## 5. 視覺方向

### 5.1 主方向：編輯式波蘭

整體保留 `Cormorant Garamond`、`Bodoni Moda`、`Noto Serif TC` 與 `JetBrains Mono` 字體組合，以及米白紙張、波蘭紅、黑色墨水、雙線分隔與細線網格。

波蘭識別以以下元素為主：

- 紅白國旗線作為頁首或重要章節的細節，不鋪滿背景。
- `POLSKA`、`WARSZAWA`、`KRAKÓW`、`WROCŁAW`、`POZNAŃ` 等正確波蘭語地名。
- 郵票或旅行章印造型，用於卷期、年份或城市識別。
- 城市座標、路線文字與 `VOL. I`、`FIELD GUIDE` 等編輯標記。

### 5.2 輔助方向：歷史式波蘭

歷史元素只作少量點綴：

- 章節編號、分隔線或「關於波蘭」章可加入低調的紋章式線條。
- 古城石牆、歷史紙張或深皇家紅可用於文化章節的局部背景。
- 王冠或類似紋章符號只在歷史語境成立時使用，不作全站重複裝飾。

所有裝飾必須服務內容層級，不能降低行程、交通、票價及訂票資訊的可讀性。

## 6. 介面與互動

- 桌機章節導覽固定在可見範圍上方，但只更換主內容區。
- 章節切換時更新網址 hash，不另建歷史狀態資料庫。
- 切換完成後，程式將焦點移到新章節標題；標題需可由程式聚焦，並保留清楚的焦點樣式。
- 目前章節或日次使用 `aria-current` 表示。
- 瀏覽器上一頁依序回到上一個章節或日次。
- 章節內允許正常短距離捲動，但不得在目前章節後接續其他主章節。
- 未知 hash 使用 `history.replaceState()` 修正為 `#overview`，不得顯示空白頁。
- Day 小於 1 時回到 Day 1；大於 8 時回到 Day 8。
- 版面在 1440、1024、768 px 不得出現水平捲動條；低於 768 px 的既有手機行為不在本階段重新設計。

## 7. 資料與元件責任

### `redesign/data.js`

繼續提供 `window.TRIP`，並作為桌機與手機共同的核心旅程資料來源。桌機的日期、日次步驟、交通、票價與訂票連結必須由此取得。

### `desktop/desktop-app.js`

負責 hash 解析、章節狀態、Day 1–8 切換、瀏覽器歷史、鍵盤操作、焦點管理及使用 `window.TRIP` 產生桌機內容。可測試的路由解析邏輯應保持獨立且不直接依賴 DOM。

### `desktop/desktop.css`

負責桌機雜誌殼層、章節導覽、多欄內容、波蘭視覺元素、焦點樣式與桌機響應式布局。只抽取經典版的視覺語言，不恢復舊長頁行為或舊裝置轉址。

### `desktop/chapters.js`

只保存桌機專屬文化、歷史、城市及實用資訊文章。不得另行定義 8 天日期、跨城班次、票價或訂票主資料。

### `index.html`

作為公開根入口與裝置分流殼層。大於等於 768 px 或帶有 `?view=desktop` 時載入桌機分章雜誌；小於 768 px 或帶有 `?view=mobile` 時載入目前的 `B_Companion`。兩種介面都使用既有 `redesign/data.js`，且手機側繼續載入目前的 PWA 核心與註冊流程。分流不能只依賴 User-Agent。

### 部署與手機檔案

`prepare-site.sh` 只新增正式桌機資產至 allowlist，持續排除 `archive/`、`tests/`、設計文件及 `.superpowers/`。`mobile.html`、manifest、`pwa-register.js` 與 `sw.js` 在本階段原則上不改；若桌機入口的最低相容修正無法避免，必須先補測試並另向使用者說明影響，不能順帶進行手機優化。

## 8. 錯誤與降級

- `redesign/data.js` 未載入或 `window.TRIP.days` 不完整時，桌機顯示「行程資料載入失敗，請重新整理」，不保留空白殼層。
- 未知章節或無效日次回到有效頁面並修正網址。
- 外部地圖與官方訂票連結在無網路時顯示需要連線的提示；不偽裝為可離線完成。
- 字體或非核心裝飾載入失敗時，使用系統襯線字體及純色分隔線，核心內容仍可閱讀。
- JavaScript 不可用時，至少保留可理解的桌機說明與手機現況連結；完整互動功能可提示需要啟用 JavaScript。

## 9. 測試與驗收

實作階段採測試先行，先讓新契約測試在目前架構下失敗，再做最小實作使其通過。

### 自動測試

- `tests/desktop-router.test.mjs`：合法章節、Day 1–8、未知 hash、日次邊界及每次只啟用一個章節。
- `tests/desktop-content.test.mjs`：Day 1–8 由 `TRIP.days` 產生、桌機文章不複製核心班次或票價、導覽與焦點契約正確。
- `tests/entrypoints.test.mjs`：根入口具備 768 px 裝置分流與兩種 query 覆寫，桌機載入分章殼層，手機仍載入既有 `B_Companion`，且現有手機入口與 PWA 行為未被意外改寫。
- `tests/deploy-contract.test.mjs`：公開輸出包含桌機核心資產，且不包含封存、測試、文件與開發檔。
- 既有測試：全部持續通過，特別是手機 PWA、資料、發布邊界與快取契約。

完整驗收指令維持 `./verify.sh`，並包含 Node 測試、bundle 一致性、JavaScript 語法檢查及 `git diff --check`。

### 實際瀏覽器驗收

在本機 HTTP 服務上驗證 1440、1024、768 px：

- 七個章節可切換且一次只顯示一章。
- Day 1–8、上一天、下一天與方向鍵正確。
- 深層 hash 重新整理、貼到新分頁及瀏覽器返回鍵正確。
- 焦點移動、`aria-current` 與鍵盤焦點樣式可見。
- 沒有水平溢出，內容不被固定導覽遮住。
- 共用日期、班次、票價與訂票連結和現有手機資料一致。
- 390、320 px 至少做回歸檢查，確認根網址仍顯示既有 PWA，且 `?view=desktop`／`?view=mobile` 覆寫正確；手機視覺改善不列入本階段驗收。

## 10. 交付與發布門檻

桌機版實作完成前，必須依序通過：

1. `./verify.sh` 全部綠燈。
2. 桌機實際瀏覽器驗收。
3. 未參與撰寫者的交叉審查。
4. 使用者實際操作桌機核心路徑並確認。

未經使用者確認，不合併至 `main`、不推送遠端，也不部署正式網站。手機版後續優化必須另立範圍，不能在桌機實作中順帶加入。
