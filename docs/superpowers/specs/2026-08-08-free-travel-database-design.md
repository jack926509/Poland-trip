# 波蘭自由行旅遊資料庫設計規格

- 日期：2026-08-08（Asia/Taipei）
- 狀態：使用者已確認實作方向
- 行程：2026-10-24 至 2026-10-31，華沙 → 克拉科夫 → 樂斯拉夫 → 波茲南 → 華沙
- 目標：把現有網站從「行程與景點說明」擴充成「可查詢的波蘭旅遊資料庫＋這趟旅程的現場操作工具」。

## 1. 成功標準

實作完成後，使用者應能：

1. 在首頁看到出發準備度、未完成項目、最近截止日與動態資料的重查時點。
2. 依城市、類別及狀態查找景點、餐飲、交通、生活、醫療與應變資料。
3. 在每日頁面直接看到上一站到下一站的地址、入口、導航、票券與備案。
4. 在斷網時仍能查看純文字地址、緊急電話、護照遺失、就醫、行李延誤與失接步驟。
5. 看出每筆資料是已查證、動態待重查、尚未確定或需使用者私人資料。
6. 不在公開網站或 Git 儲存庫中暴露護照號碼、完整卡號、訂位代碼、保單號或健康隱私。

## 2. 架構選擇

採用「雙層資料庫」：

- **旅遊資料庫層**：收錄可重複利用的地點、營運規則、票價、官方來源、安全與生活資料。
- **行程操作層**：參照資料庫記錄，組成本次 8 天的每日導航、訂票狀態、備案與離線卡。

不引入後端或資料庫服務。維持現有 Node.js 建置器與靜態 HTML 架構，以 ES module 資料檔作為唯一來源，使 GitHub Pages 上仍可運作。

## 3. 資料分類

### 3.1 地點與參觀

- 景點、博物館、教堂、公園、觀景台、車站、機場、餐廳與商店。
- 欄位：官方名稱、城市、完整地址、經緯度、正確入口、最近站、官網、導航、開放日、營業時間、末入、預估停留、票價、預約要求、寄包、廁所、樓梯／電梯、室內外比例。

### 3.2 交通與轉場

- 航班、聯運轉機、城際火車、往返奧斯威辛交通、機場交通、四城市內票制、車站設施與行李寄放。
- 未開賣班次不寫成固定時間；月台、改道與機場櫃位標為當日動態查詢。

### 3.3 餐飲

- 米其林名單、傳統料理、行程主選、同區備案與便利備案。
- 欄位：官方菜系特色、分店地址、當日營業、最後點餐、訂位、候位、付款、過敏溝通與查證日。
- 未取得店家來源的動態營業時間不顯示為已確認。

### 3.4 生活與金流

- SIM／eSIM、離線地圖、付款、DCC、ATM、現金備援、小費、飲水、廁所、插座、充電、超商與非營業週日。

### 3.5 安全、醫療與入境

- 112／999、旅平險操作、就醫、夜間藥局搜尋入口、護照遺失、行李延誤、轉機失接、駐波蘭代表處、旅外登錄、護照與 ETIAS。
- 駐波蘭代表處地址改為外交部 2026-07-28 資料：`30th Floor, Ul. Emilii Plater 53, 00-113 Warsaw, Poland`。

### 3.6 退稅、文件與旅程狀態

- TAX FREE 資格、200 PLN 條件、單據、商品所在行李、海關確認與退款狀態。
- 住宿、航班、火車、景點與餐廳預約的完成狀態。

## 4. 統一資料模型

所有動態資料至少帶下列欄位：

```js
{
  id: 'stable-machine-id',
  category: 'place | transit | dining | practical | safety | document',
  cityKey: 'WAW | KRK | WRO | POZ | PL | ROUTE',
  title: '使用者看得懂的名稱',
  summary: '可離線閱讀的重點',
  status: 'verified | recheck | pending | private-required',
  sourceUrl: 'https://official.example/',
  verifiedAt: '2026-08-08',
  recheckAt: '2026-10-17',
  offlineNote: '斷網時仍能使用的資訊',
  private: false
}
```

地點資料另有 `address`、`coordinates`、`entranceNote`、`mapsUrl`、`officialUrl`。票券另有 `visitDate`、`bookingStatus`、`offlineCopyStatus`、`lastAdmission`。動線另有 `fromId`、`toId`、`mode`、`plannedMinutes`、`bufferMinutes`。

## 5. 頁面與導覽設計

### 5.1 首頁「出發準備度」

- 顯示 P0 未完成數、最近確認期限、下一張要買的票、ETIAS 狀態與離線包狀態。
- 這是摘要而非全部資料；每張卡連到對應資料庫區塊。

### 5.2 新增「自由行資料庫」頁

- 路徑：`practical/database.html`。
- 页首依類別、城市與狀態顯示目錄與統計。
- 區塊：出入境、航空行李、火車權益、網路離線、金流、醫療保險、緊急應變、行李寄放、週日節日、退稅、無障礙、補水廁所與充電。
- 每筆顯示狀態、查證日、重查日與官方來源。

### 5.3 每日頁「今天怎麼走」

- 現有時間表保留。
- 已有可靠地點的行程步驟增加純文字地址、入口說明、導航連結與官網。
- 動態市內車號只當作規劃，顯示當日查 Jakdojade 的提示。
- 每天附「晚間準備」：充電、下載明日票券、截圖集合點、確認天氣與月台。

### 5.4 SOS 與文件庫

- 資料庫頁最上方放離線 SOS 卡：112、999、駐波蘭代表處、外交部緊急聯絡中心與保險救援待填狀態。
- 電話用 `tel:`，地址同時有純文字與地圖。
- 護照遺失、就醫、行李未到、轉機失接與卡片遺失均使用一步一步的操作卡。

## 6. 狀態、時效與來源規則

| 狀態 | 用途 |
|---|---|
| `verified` | 已由資訊擁有者的官方來源確認 |
| `recheck` | 當前可用，但班次、活動、營業或規定可能在出發前變動 |
| `pending` | 官方尚未公告、開賣或無法確認 |
| `private-required` | 只能由旅客的訂單、保單、航空訂位或卡片資料提供 |

- 沒有 `sourceUrl` 的公開動態事實不得標為 `verified`。
- 官方來源、查證日與結論必須同時顯示。
- 火車、航班、餐廳、天氣、ETIAS、臨時閉館和月台不使用沒有日期的靜態斷言。

## 7. 私人資料邊界

- Git 內只放欄位結構、公開事實與「待填」狀態。
- 不建立會被靜態網站複製到 `dist/` 的私人資料檔。
- 訂位代碼只可顯示末 4 碼；公開版只顯示是否已填。
- 完整護照號碼、卡號、安全碼、保單號、醫療史與家人聯絡方式不寫入儲存庫。

## 8. 無障礙與離線

- 新頁使用真實標題層級、表格標頭、焦點狀態及跳至主內容連結。
- 狀態不只靠顏色，同時顯示文字標籤。
- 所有緊急操作卡與地址在不載入外部地圖、字型或 JavaScript 時仍可閱讀。
- 資料庫頁可在 390 px 寬度閱讀，不產生整頁水平捲動。

## 9. 實作分期

內容量大，但每階段都必須產出可用頁面：

### 第一階段：資料骨架、準備度與 SOS

- 建立統一資料模型、資料庫頁、首頁準備度與狀態統計。
- 更新駐波蘭代表處，補入緊急、入境、ETIAS、醫療、護照遺失、航空行李、金流、網路與退稅內容。

### 第二階段：每日導航與票券狀態

- 將已排定景點、車站、餐廳與機場接回每日步驟。
- 新增入口、導航、上下站、緩衝、票券與晚間準備。

### 第三階段：生活節點與低負荷備案

- 補齊廁所、補水、充電、無障礙、極端天氣與少走路替代。
- 這些資料只在有場館或營運單位來源時標為已確認。
