# POLSKA「紙上旅行誌」正式改版設計規格

- 日期：2026-08-25（Asia/Taipei）
- 使用者選定方向：方案 C｜紙上旅行誌
- 狀態：正式修改計劃撰寫中，尚未進入實作
- 適用範圍：23 頁正式靜態網站與單檔版旅遊指南

## 1. 改版目標

將現行偏資料卡片與管理介面的 POLSKA 網站，改造成以城市照片、章節編排、日期節奏與紙本閱讀感為核心的「紙上旅行誌」。網站仍須保有旅途中快速查找行程、導航、待辦、票務、資料庫與地圖的效率，不能為了視覺效果犧牲正確性或操作性。

做完後，使用者應能在首頁先感受到旅行誌封面與四城旅程脈絡，再進入某一天或某座城市閱讀；在手機上仍能於三次點擊內抵達每日行程、城市指南或實用資訊。

## 2. 已確認的設計方向

### 2.1 視覺語言

- 主色：暖紙色、深棕墨色、墨紫與低飽和磚紅。
- 攝影：只使用現有 `assets/photos/*.webp` 四城授權照片；不新增未查證或無授權來源的圖片。
- 字體：拉丁標題沿用 `Playfair Display`；中文內文沿用 `Noto Sans TC`，不以手寫字承載長文。
- 紙本元素：刊號、頁碼、章節標籤、細線分隔、照片說明與郵戳感裝飾只作輔助，不影響閱讀順序。
- 狀態色：紅色只用於風險與待處理；綠色只用於已確認或完成；不得把狀態顏色當成大面積裝飾。

### 2.2 資訊層級

1. 首頁先呈現封面、旅程日期、路線與四城照片。
2. 8 天行程改為旅行誌目錄式章節，保留日期、城市、主題、待訂狀態與完整連結。
3. 四座城市改為攝影章節入口，照片、中文／波蘭文名稱與城市氣質先行。
4. 待辦與資料狀態縮成可快速掃讀的資訊條，不搶過旅行內容主視覺。
5. 實用工具維持完整入口，但置於旅行章節之後。

## 3. 正式網站架構

沿用既有資料驅動架構：

```text
src/data/*.js
  ↓
src/templates/*.mjs
  ↓
build.mjs
  ├─ dist/（23 頁正式網站）
  └─ poland-travel-guide-2026.html（單檔版）
```

原型的 `prototype/uxui-three-directions/`、方案切換器與 `?variant=` 參數不進入正式網站。正式改版以相同視覺語言重新編寫正式模板結構與 `src/styles/main.css`，不直接複製原型 HTML。

旅遊資料、票價、狀態、地圖圖釘與公開／私人資料邊界不在本次改動範圍。所有內容仍從 `src/data/*.js` 產生，禁止直接編輯 `dist/` 或根目錄產生檔。

## 4. 頁面設計

### 4.1 共用外框

- 導覽改為旅行誌刊頭：品牌、期別與三組既有原生下拉選單。
- 保留 `details/summary` 導覽、跳至內容連結、`aria-current` 與現有 `nav.js` 的單選單展開行為。
- 每頁由 `renderLayout` 接收 `pageKind`，輸出穩定的頁面類型 class，供首頁、每日、城市與實用頁套用不同章節樣式。
- 頁尾保留資料查證日期與動態資訊警語，不改成裝飾性文案。

### 4.2 首頁

- 使用第一座城市的既有華沙照片作為封面主圖，搭配 POLSKA、日期、8 天 7 夜與四城路線。
- 待辦總數及資料狀態以窄幅資訊條呈現，完整待辦仍連往 `practical/todos.html`。
- 8 天行程以旅行誌目錄呈現，每一章保留 Day、日期、城市、標題、摘要、待訂數與連結。
- 四城入口改為含圖片的章節卡，使用 `city.photo.hero` 或 `city.photo.thumb`，每張圖片具描述性 `alt`。
- 航班與實用工具保留，但視覺層級低於旅程與城市章節。

### 4.3 每日行程頁

- 頁首改為當日章節跨頁感：Day、日期、標題、城市、強度、天氣與類型。
- 每日主圖依當天城市選用既有城市照片；跨城日採目的地城市，Day 8 保留華沙。
- 行程時間表、當天交通、硬性時間、可壓縮項目、待訂、風險、導航地址、備案、餐飲、拍照與晚間準備全部保留。
- 手機時間表維持卡片化欄位標籤，不依賴水平捲動。

### 4.4 城市頁

- 頁首直接使用該城市 hero 圖片，疊加中文名、波蘭文名、城市氣質與章節標籤。
- 城市故事置於地圖之前，形成「先閱讀、再查找」的順序；地圖、景點、餐廳、備案與拍照資訊不刪減。
- Leaflet 容器、圖釘資料屬性、圖例及載入腳本接口保持不變。

### 4.5 實用資訊與資料庫

- 訂票、待辦、餐廳、門票、交通、購物、安全、行前提醒、資料更新儀表板與自由行資料庫使用較克制的「附錄」版式。
- 表格、篩選器、按鈕、狀態標籤與 `aria-live` 行為保持原功能。
- 資料庫快速篩選在手機上不得自動搶回搜尋框焦點，不得叫出鍵盤。

### 4.6 單檔版

- 保留 23 個章節的 hash 切換、三組下拉目錄、ID／`for`／ARIA 參照改寫、前後頁導航、資料庫 inline filter 與列印時展開全部章節。
- 單檔外框同步使用紙上旅行誌色票與刊頭，不變更 bundling 演算法。
- 單檔版仍不得依賴本機 CSS、其他本機 HTML 或外部資料篩選腳本。

## 5. 手機、可及性與動態效果

- 驗收尺寸：1280×900、390×844、320×844。
- 正文不得小於 16px；補充標籤可低於 16px，但不得承載主要操作或必要資訊。
- 所有按鈕、摘要與主要導覽連結的觸控高度至少 44px。
- 所有頁面 `document.documentElement.scrollWidth === document.documentElement.clientWidth`。
- 保留清楚的 `:focus-visible`；圖片必須有合適 `alt`；裝飾圖形設為 `aria-hidden="true"`。
- 動畫只允許淡入、輕微位移與 hover 紙張感；`prefers-reduced-motion: reduce` 時取消動畫與平滑捲動，內容不得因此隱藏。
- 手機導覽展開後不得被照片、地圖或內容卡遮住。

## 6. 必須保留的既有契約

- 正式站仍產出正好 23 個 HTML 頁面。
- 所有內部連結維持相對路徑，支援 GitHub Pages 子路徑。
- 8 天、4 城、所有實用頁、14 項待辦與自由行資料庫入口完整存在。
- 公開輸出不得出現訂位代碼、護照、保險或付款資料。
- 城市地圖合計 56 個圖釘，已驗證與待確認狀態不可被視覺改版改寫。
- 資料庫的 XSS 跳脫、安全 HTTPS 來源與篩選無結果狀態保持有效。
- 正常多頁版使用外部 `database-filter.js`；單檔版只嵌入同一份程式碼。

## 7. 不做的項目

- 不修改任何旅遊事實、價格、營業時間、地址或訂票狀態。
- 不新增內容管理系統、登入、雲端資料庫或即時 API。
- 不新增照片下載、圖片生成或授權研究。
- 不恢復已歸檔的 PWA、React 或舊版雙介面。
- 不在本次計劃中推送、合併或部署；發布必須另經使用者確認。
- 不把三方向原型、切換器或落選方案帶入正式輸出。

## 8. 白話驗收條件

1. 打開首頁，第一眼看到的是旅行誌封面、波蘭四城照片與旅程日期，不再像資料管理儀表板。
2. 手機打開首頁，不用左右滑即可看完，並能清楚點進任何一天、城市與實用工具。
3. 任一每日頁仍找得到時間、交通、地址、風險、待訂與下一天入口。
4. 任一城市頁仍能操作地圖並看到景點、餐廳、備案與拍照資訊。
5. 自由行資料庫搜尋與快速篩選維持可用，結果數與空狀態正確。
6. `env -u NODE_OPTIONS ./verify.sh` 全數通過，瀏覽器 console 沒有 error。
7. 另一個 AI 依 diff、驗收條件與風險提示完成交叉審查，使用者再實際操作核心路徑。
