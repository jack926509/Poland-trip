# 手機版 UX/UI 重新設計 — 設計規格

- 日期：2026-07-26（Asia/Taipei）
- 分支：`feat/mobile-premium-reskin`（本規格的實作應開新分支 `feat/mobile-uxui-redesign`）
- 決策依據：提案頁 https://claude.ai/code/artifact/e8bc37f9-9826-4925-a680-7a9b17eeafe0
- 使用者選定：**方案 A ＋ 結構① ＋ 範圍② ＋ 邊界①**

## 1. 這次要解決什麼

現行手機版（`/mobile.html`）的四個具體問題，來自 2026-07-26 的審查與提案比對：

1. hero 是漸層色塊而非照片，整頁沒有任何影像，辨識不出「今天在哪座城」。
2. 底部四格是純文字無圖示，四格等寬，辨識度低。
3. 首頁是一疊「標籤＋方框」（今日硬限制／必訂票／可壓縮），像表單不像 App，沒有數字概覽。
4. 記帳頁四張分類卡全用紅字（含三張 NT$0），紅色失去訊號意義。

目標不是「變漂亮」，是讓使用者在波蘭當地單手、快速拿到當天要用的資訊。

## 2. 設計語言（方案 A：暖白紙卡・照片主導）

沿用使用者自建的 SEOUL Travel Hub 語言，因為它已被實際使用驗證過。

### 色票

| 用途 | 值 | 說明 |
|---|---|---|
| 底 | `#F7F4EF` | 暖白紙 |
| 卡面 | `#FFFFFF` | 白卡 |
| 主文 | `#1B1917` | 墨（也用於選中態實心藥丸） |
| 次文 | `#7C736B` | 灰褐 |
| 弱文／標籤 | `#8A8078` | |
| 主數字卡 | `#33261E` 底 ＋ `#C9A46F` 數字 | 深咖啡卡只用在「總花費」與同級唯一主角 |
| 分隔 | `#F1EDE6` | |
| 訊號・警示 | `#B5502E` | 只給硬限制、最後入場、誤點 |
| 訊號・完成 | `#2F6B4F` | 只給已完成、達標 |
| 標籤・交通 | `#E8EFF8` 底 `#3F6491` 字 | |
| 標籤・要票 | `#FDEDE3` 底 `#C2653A` 字 | |

紅色只作訊號，不作裝飾——這是取代現況「滿頁紅字」的硬規則。

### 字

- 中文正文與標題：系統 `-apple-system`（iOS 實際渲染 PingFang TC），標題 600 字重。
- 拉丁 display（城市名、Day、金額）：`"Hoefler Text","Iowan Old Style",Palatino,serif`。
  **必須加 `font-variant-numeric: lining-nums tabular-nums`**——Hoefler Text 預設走舊式數字，會把 `Day 1` 排成 `Day I`（提案頁已踩過這個坑）。
- 小標籤／數據：等寬 `"SF Mono",ui-monospace`，`letter-spacing:.1em`，大寫。
- 型階：31 / 26 / 19 / 16.5 / 14 / 12.5 / 10.5 px。

### 元件

- 卡：`border-radius:18px`、`box-shadow:0 1px 2px rgba(27,25,23,.05),0 10px 22px -14px rgba(27,25,23,.28)`。
- 分段藥丸：未選白底、選中 `#1B1917` 實心白字；橫向可捲時父層 `overflow-x:auto`、`overflow-y:hidden`。
- 統計四宮格：白卡內四等分，數字用等寬 tabular-nums，下方 10px 說明字。
- 底部導覽：圖示在上、標籤在下，選中態墨色＋600 字重。
- 子頁詳情：底部抽屜，含拖曳把手、關閉鍵、主行動（實心墨）＋次行動（白底描邊）。
- 不使用 emoji 當區段標記，用單色字符（`◈ △ ◷ ⇄`）或純文字小標。

## 3. 資訊架構（結構①）

底部四格：**首頁 ／ 行程 ／ 交通 ／ 記帳**

- 記帳從第二層提到第一層（旅途中每天點好幾次）。
- 交通保留在第一層（本趟跨四城、五段長途火車，是最容易出事的資訊）。
- 「更多」分頁取消。原本藏在其中的五個工具改由**首頁右上角「⋯」選單**進入：Photo Map（改名為「拍照清單」）、匯率換算、打包清單、SOS 緊急卡、實用資訊。
- 「⋯」選單與所有子頁沿用同一個抽屜模式，並且必須修掉第 6 節的 M4（焦點與 Escape）。

## 4. 各畫面規格

### 4.1 首頁

由上而下：

1. **城市 hero**（高 230px）：真實城市照＋下方深色漸層壓字；左下 `DAY n · 日期`、城市名（display 31px）、`Warszawa · 抵達日`；右下輪播指示點。四城輪播，`prefers-reduced-motion: reduce` 時不自動輪替（現行行為已正確，保留）。
2. **統計四宮格**：今天第幾天 ／ 白天氣溫 ／ 已花 NT$ ／ 預算用掉 %。
3. **今日重點卡**：`Day n`（display）＋日期城市，標題、一行敘述，右上強度標籤。
4. **今日硬限制卡**：`△` ＋ 硬限制內容（訊號紅只出現在字符與標題）。
5. **下一段交通卡**：時間、`WAW → KRK`、車種標籤、抵達時間與票價區間；含 4.5 的倒數。
6. 右上角「⋯」開工具選單。

移除現況的「必訂票／可壓縮」獨立方框——併入今日重點卡的敘述行，避免表單感。

### 4.2 行程

- 頂部 `Day 1–8` 橫向藥丸（可捲，`overflow-x:auto`）。
- 當日抬頭卡：`Day n`、日期、城市轉場、標題。
- 時間軸列表：左側時間（等寬）、62×52 縮圖、標題＋分類標籤（交通／要票／餐飲）、一行說明。
- 點任一項開底部抽屜：大圖、注意事項、小貼士、地圖導航與複製地址兩個行動。

### 4.3 交通

保留現有「今日訂票」內容，改用 4.2 的列表樣式；五段長途火車各一列，含 4.5 倒數。

### 4.4 記帳

- 深咖啡主卡：`138.00`（display，PLN）、`≈ NT$1,311`、匯率、預算進度條、`已花 / 預算`。
- 分類四宮格取代現況四張紅字卡：餐飲／交通／門票／購物，`0` 顯示為 `0` 不顯示 `NT$0`。
- Day 篩選藥丸（橫向可捲）。
- 明細列：左品項＋`分類 · 付款 · Day`，右 `88 PLN` ＋ `≈NT$836`；金額格式統一兩位小數。
- 右下浮動「＋ 記一筆」。

## 5. 三個補強功能（範圍②）

### 5.1 退稅門檻提醒

**已查證的事實（2026-07-26 查，來源見文末）：**

- 門檻：**單張收據 200 PLN 含稅**，同一店家一次交易；**不同收據、不同店家不可合併**。
- 標準 VAT 23%（部分 8% / 5%），實際可拿回約 10–18%。
- 須於購買後三個月內離境；波蘭已全面電子 TAX FREE，離境時海關線上確認。
- 本趟離境點為華沙（Day 8 華沙 → 多哈，離開歐盟），退稅在 WAW 辦。

**規格：**

- 記帳新增一筆且分類為「購物」時，判斷該筆 PLN 金額：
  - `>= 200`：顯示「這筆可辦退稅 · 預估可退 NT$xxx–xxx（10–18%）」，並在明細列加「可退稅」標籤。
  - `150–199`：顯示「距離退稅門檻還差 xx PLN（同一張收據才算）」。
  - `< 150`：不提示。
- 記帳頁加「可退稅」篩選，列出所有達標項目與預估總額區間。
- **不可**做成同店累積——與規定不符，會誤導使用者。
- 提示文案須含「同一張收據」字樣，避免誤解。

### 5.2 下一班車倒數

- 資料來源：`redesign/data.js` 現有的 `trains` 陣列（`seg / date / type / dep / arr / dur / price`）。
- 首頁與交通頁顯示「下一段長途車」：日期、`dep`、路段、車種，以及與現在時間的差距（`還有 14 小時` / `還有 45 分` / 已出發則顯示下一段）。
- 時間比較以**波蘭當地時間**為準（歐洲中部時間；10/24–10/31 期間為 CET，UTC+1，10 月最後一個週日結束日光節約——2026 年為 10/25，故 10/24 為 CEST(UTC+2)、10/25 起為 CET(UTC+1)）。實作時以固定偏移量表處理，不引入時區函式庫。
- 沒有下一段車時顯示「今天沒有長途車」。

### 5.3 拍照清單（原 Photo Map）

- 現況：四座城市的打卡開關，key `polska.photomap.v1`，以中文城市名為 key。
- 改為景點層級清單：每項含城市、景點名、建議 Day、建議時段與光線說明、完成開關。
- 內容依據：10 月底波蘭日落約 16:30–16:45，藍調時段短，這是「建議時段」的實用價值來源。景點清單由 `data.js` 新增欄位提供。
- 完成度顯示為統計四宮格（全部／今日／已完成／完成度 %）。
- **舊 key 遷移**：`polska.photomap.v1` 從「城市名 → bool」變為「景點 id → bool」。必須寫遷移：舊資料存在時，把已打卡城市對應到該城市第一個景點，並保留原 key 一份備份（`polska.photomap.v0.backup`），不可直接丟棄使用者資料。

## 6. 一併修掉的審查發現

來自 2026-07-26 審查（scratchpad `POLSKA-審查總結-2026-07-26.md`）：

- **M1** `redesign/pwa-core.js:75-85`：`readJSON` 不驗型別，`polska.expenses.v1` 存成非陣列會讓 `:106` 的 `.forEach` 拋錯 → 整支 App 白頁。加型別守門，型別不符回 fallback 深拷貝。
- **M2** `redesign/B-companion.jsx:511/571/620`：`B_PhotoMap`／`B_FxTool`／`B_Packing` 丟棄 `writeJSON` 回傳值 → 寫入失敗無提示。三處接回傳值並顯示與記帳相同的警語。
- **M3** `redesign/B-companion.jsx:373`：驗證失敗直接 return，無提示。改為 `setFormError` ＋ `<p role="alert">`。
- **M4** `redesign/B-companion.jsx:918-931`：子頁宣告 `role="dialog" aria-modal="true"` 但 Escape 不關、背景可滾動、焦點不進子頁。把 `subpage` 併入 Escape 與 scroll lock 條件；開啟時 focus 子頁標題、關閉時還原開啟者焦點（比照 `drawerReturnFocusRef`）。
- 低優先：`README.md:15,19` 的 `polska-v16` 更正為實際版本；「實用資訊」頁「1 PLN ≈ 8 TWD」改為讀即時匯率設定；金額加千分位。

## 7. 照片策略（本規格唯一的待確認假設）

方案 A 依賴照片。使用者尚未前往波蘭，無自有照片。

**假設（若使用者不同意，只需改本節）：** 由我取得 Wikimedia Commons 上公有領域或 CC 授權的四城照片，處理後入庫：

- 四張城市 hero（華沙、克拉科夫、樂斯拉夫、波茲南）＋ 行程縮圖沿用城市照裁切版。
- 格式 WebP，hero 長邊 1200px、每張 ≤ 70KB；縮圖 200px、每張 ≤ 12KB；**全部影像總計 ≤ 400KB**。
- 存放 `assets/photos/`，授權與來源記錄於 `assets/photos/CREDITS.md`。
- 每張圖都必須進 `sw.js` 的 `PRECACHE_URLS` 與 `prepare-site.sh` 的 allowlist（見第 8 節），否則線上 404 或離線缺圖。

替代方案（若不要照片）：改用程式生成的城市天際線色塊（Canvas/SVG），零外部素材、零體積增加，但視覺說服力低於照片。

## 8. 部署與離線契約（最容易漏的一段）

- `sw.js:3` `CACHE_VERSION` 由 `polska-v17` 升至 `polska-v18`，`PRECACHE_URLS` 內所有 `?v=` 查詢字串同步更新，`index.html`、`mobile.html` 內的版本字串亦須一致（現況分別 9 處與 6 處）。
- 新增的照片與任何新檔案，必須同時加入 `prepare-site.sh` 的 allowlist——`_site` 是白名單複製，漏加就是線上 404。
- `caches.addAll` 是原子操作：`PRECACHE_URLS` 任何一項取不到，整個離線功能失效。實作後必須實跑 `prepare-site.sh` 並逐項比對。
- `install` 不呼叫 `skipWaiting()` 的行為保留（使用者確認後才更新）。

## 9. 不做（YAGNI）

- 桌機版 `/` 與 `desktop/` 完全不動（邊界①）。
- 不做可編輯行程（拖曳排序、改時間）。
- 不做照片上傳——localStorage 約 5MB，幾張手機照就爆，要改 IndexedDB，不在本次範圍。
- 不做即時天氣、即時匯率 API：離線優先的 PWA 不引入執行時網路依賴，溫度與匯率維持靜態資料與手動設定。
- 不改 `data.js` 既有欄位語意，只新增欄位。

## 10. 驗收條件

1. `./verify.sh` 全綠：`node --test` 全數通過、build 後 `redesign/dist/B-companion.js` 與提交版 byte-identical、8 個 `node --check` 通過、`git diff --check` 乾淨。
2. 新增測試契約：四分頁結構（首頁/行程/交通/記帳）、退稅門檻邏輯（199 不提示達標、200 提示、不同筆不合併）、倒數計算、photomap 舊 key 遷移、M1–M4 各一條回歸測試。
3. 真實瀏覽器（headless Chrome）驗收，390px 與 320px 各跑一遍：四分頁與五個工具子頁零水平溢出、零 console error；記帳／拍照清單／打包清單三項寫入重整後保留；離線重開可用（含照片）。
4. 由 fresh-context subagent 驗收，不自驗。
5. 非工程師視角走一遍：打開首頁能在三秒內回答「今天在哪、下一班車幾點、還剩多少錢」。
