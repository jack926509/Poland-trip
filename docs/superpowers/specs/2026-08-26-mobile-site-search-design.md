# 手機優先全站旅遊搜尋設計規格

## 目標

在全部 23 個多頁網站頁面與單檔版頂部提供同一套旅遊搜尋。使用者能直接搜尋火車時刻、餐廳位置、景點地圖、城市特色與網站其他公開內容，無須先知道資料放在哪一頁。

## 已確認方向

- 搜尋範圍：整個旅遊網站，不只限於「自由行資料庫」。
- 入口位置：每一頁頂端。
- 介面組合：A「即時搜尋列」＋ B「快捷分類」。
- 裝置優先順序：先滿足手機閱讀與單手操作，再調整桌面版排。
- 視覺方向：延續 C「紙上旅行誌」的紙色、墨紫、磚紅與編輯式排版，不引入新的視覺系統。

## 使用者體驗

### 搜尋列

- 多頁版放在主導覽下方，手機為滿寬；桌面版與刊號、導覽維持清楚階層。
- 輸入框高度至少 48 px，清除與結果連結的可點區至少 44 px。
- 標籤為「搜尋整個旅遊網站」，提示文字使用真實範例：「火車、餐廳、景點、城市特色」。
- 無輸入時不顯示結果清單，但顯示四個快捷分類：火車、餐廳、地圖、城市。
- 搜尋使用即時篩選；關鍵字與快捷分類可同時作用。

### 搜尋結果

- 結果依相關度排序：標題完全命中、標題部分命中、說明／關鍵詞命中。
- 每筆為單欄卡片，顯示類型、標題、城市／路線與一行說明。
- 最多同時顯示 8 筆，避免手機結果面板過長。
- 有 Google Maps 位置的餐廳或景點可顯示「開啟地圖」次要操作；主要操作仍為前往網站內對應頁面。
- 無結果狀態顯示「找不到相符資料」，並提供「清除條件」作為唯一下一步。
- 結果數量使用 `aria-live="polite"` 公告。

### 鍵盤與無障礙

- 輸入框使用 `type="search"`、可見 label 與 `aria-controls`。
- `Escape` 清除搜尋並關閉結果；快捷分類按鈕維持 `aria-pressed`。
- 所有互動元素使用原生 input、button 與 a，保留清楚 `:focus-visible`。
- 不新增動畫；原有 `prefers-reduced-motion` 契約不變。

## 搜尋資料模型

每筆公開搜尋資料為：

```js
{
  id: 'train-waw-krk',
  type: 'train',
  typeLabel: '火車',
  title: '華沙 → 克拉科夫',
  meta: '10/25 · 目標 09:00 → 約 11:25',
  summary: 'EIP · 尚未確認班次 · 待開賣',
  href: 'practical/booking.html#rail-itinerary',
  mapUrl: '',
  searchText: '華沙 克拉科夫 WAW KRK 火車 EIP ...'
}
```

索引包含：

1. 23 個公開頁面的頁級資料，關鍵字由建置後的 `<main>` 公開文字產生。
2. 5 筆城際火車路線。
3. 餐廳探索、主推、備案與已查營業時間資料，以城市＋店名去重。
4. 56 個城市地圖圖釘與景點資料。
5. 4 座城市的中外文名、特色、亮點與故事關鍵字。
6. 8 日行程的標題、城市與步驟關鍵字。

索引不讀取私人資料條目，不包含護照、保險、付款、訂單號或私人住址。搜尋完全在瀏覽器本機執行，不傳送搜尋字串。

## 多頁版與單檔版

- 多頁版：`renderLayout()` 輸出共用搜尋元件、路徑前綴與索引佔位；`build.mjs` 在 23 頁皆建置後產生索引並注入各頁 JSON，頁面載入 `assets/site-search.js`。
- 單檔版：搜尋元件位於單檔刊頭下方；建置器嵌入同一份索引與搜尋程式，不依賴本機外部檔。
- 單檔結果連結改寫為 `#page-...` 與頁內前綴 anchor，沿用現有單檔 ID 改寫規則。

## 效能與降級

- 全部索引在建置時產生，頁面不發出搜尋 API 請求。
- 輸入時搜尋現有記憶體內陣列，不新增第三方套件。
- JavaScript 不可用時，原有主導覽與「自由行資料庫」仍可瀏覽；搜尋列顯示前往資料庫的降級連結。

## 驗收條件

1. 23 個多頁頁面都有同一個全站搜尋入口。
2. 在 390 px 寬手機畫面，搜尋輸入框至少 48 px，互動元素至少 44 px，無水平溢出。
3. 搜尋「火車」可找到路線與時刻；搜尋「U Fukiera」可找到餐廳與地圖；搜尋「小矮人」可找到樂斯拉夫城市特色。
4. 火車、餐廳、地圖、城市快捷分類可切換，且 `aria-pressed` 狀態正確。
5. Escape 可關閉結果，清除後回復快捷分類。
6. 單檔版搜尋能跳到正確章節，不載入外部本機搜尋程式。
7. 建置、完整測試、地圖稽核與多頁／單檔瀏覽器驗收全數通過。

## 不在本次範圍

- 不新增網路搜尋、雲端搜尋、搜尋紀錄或個人化。
- 不改動旅遊事實、時刻、票價、店家資料與私人狀態。
- 不部署、不推送、不合併分支。
